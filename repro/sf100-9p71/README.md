# SF100 9.710381-second checkpoint

This branch restores the full measured November 11 optimization snapshot on base `b5197997d305e44197616ada9f043084afdfeb9d`. It contains the early plan and execution/codec work, with no later research or host-spilling changes. Original identifiers and attribution notices are preserved. All 262 archived cuDF source files match `source-sha256.txt` byte-for-byte.

The result is **9.710381 seconds**: the mean of two suite totals, **9.720601** and **9.700161** seconds. Each total sums the 22 query medians; each query ran six times, discarding the first and taking the median of the other five. All results in both rounds passed the independent CPU reference, including ordering checks. These are archived measurements, not a new benchmark of this publication.

Hardware: AWS g6.8xlarge, one L4. Dataset: SF100, 14 Parquet files, INT32 keys where applicable and DECIMAL amounts, generated by `tpchgen-rs` revision `8e9a6ef307d74c2b60ad02ff287920f53193e26e` with eight jobs. Input is **encoded pinned host memory, not GPU-resident input**. Loading/encoding and plan construction are outside the timer; query execution and native CPU result collection are inside it. Per-query and per-round results are in `measured-results.json`.

## Build

Use the `adapters-cuda` Docker Compose service. The measured image was:

`ghcr.io/facebookincubator/velox-dev@sha256:ce022e22a073452064026f7ace08caeccefe24d50bc283580ccf1a94fec7e10c`

The build used GCC14.2.1, CUDA12.9.86 and cuDF `02f215d2bb7a4840ebbd5b81532ae717abea5054`. **Override the base branch's cuDF dependency pin**, which is older:

```sh
git clone https://github.com/rapidsai/cudf.git vendor-cudf-02f215d
git -C vendor-cudf-02f215d checkout 02f215d2bb7a4840ebbd5b81532ae717abea5054
docker compose -f docker-compose.yml -f repro/sf100-9p71/image.yml run --rm -T --no-deps adapters-cuda bash -lc '
  make cmake-cudf BUILD_BASE_DIR=_build_docker BUILD_DIR=release BUILD_TYPE=Release CUDA_ARCHITECTURES=native EXTRA_CMAKE_FLAGS="-DVELOX_ENABLE_ARROW=ON -DVELOX_ENABLE_PARQUET=ON -DVELOX_ENABLE_BENCHMARKS=ON -DVELOX_ENABLE_BENCHMARKS_BASIC=ON -DFETCHCONTENT_SOURCE_DIR_CUDF=/velox/vendor-cudf-02f215d" &&
  cmake --build _build_docker/release --target velox_cudf_tpch_benchmark -j12
'
```

## Run

The flags and properties are essential; this is not the benchmark's default configuration. From the repository root:

```sh
sha256sum -c repro/sf100-9p71/source-sha256.txt
# Run the dataset checksum manifest from the SF100 dataset directory.
bash repro/sf100-9p71/run.sh /absolute/path/to/tpch_sf100 /absolute/path/to/new-results
```

The replay script uses one driver, all 22 queries, six repeats, the recorded plan/codec switches, and the exact Q11 threshold. Do not compare this number with GPU-resident input or a plans-only branch. The branch is a historical research snapshot, not an upstream-ready PR.
